# Manage the add-ons in Git

> How-to · [Documentation](../../README.md#documentation)

Have Argo CD manage the add-ons (Cilium, Argo CD itself, cert-manager,
Headlamp, Longhorn, the gateway, ...) from the repository instead of Helm, and
change them afterwards. Why and how it works:
[GitOps and add-ons](../explanation/gitops.md#add-ons-in-git). What gets
written: [Repository files](../reference/repository-files.md).

## Move the add-ons to Git

Needs a cluster with an `argocd` section ([Set up GitOps](set-up-gitops.md)).

1. Create a second credential with **write** access, used only from the host
   to push: an SSH deploy key with write permission, or a token. Argo CD keeps
   its read-only one.
2. Enable the add-ons:

   ```yaml
   argocd:
     addons:
       enabled: true
       pushSshKeyFile: forgejo/gitops-push-key    # or pushTokenFile for http(s)
   ```

3. Apply:

   ```sh
   ./deploy-talos.py argocd -f lab.yaml
   ```

   The script renders the add-ons into `clusters/<name>` (or `addons.path`),
   commits and pushes them, applies the app-of-apps once, and waits until
   everything is Synced and Healthy. Existing Helm releases are adopted, not
   recreated.

4. Check: `kubectl -n argocd get applications` lists `addons` and one
   Application per add-on, all Synced and Healthy.

The repository must provide the AppProjects the generated Applications use:
`platform-infra` and `platform-services` unless `argocd.addons.projects`
names others.

## Change an add-on

With `addons.content: generate` (default), the cluster file is the source:

1. Edit the section (e.g. `monitoring.retention`, `cilium.version`).
2. Run `./deploy-talos.py argocd -f lab.yaml` (or `headlamp`, `longhorn`).
3. The script pushes the new files and waits for the sync.

Don't edit generated files in the repository: the next run overwrites them.

## Make Git the source instead

Set `addons.content: reuse`. Files already in the repository are then kept as
they are, your edits included; only missing files are written. Make changes
in the repository. To have the script write a file again, delete it from the
repository and run `argocd`.

## Add your own Applications

Put them in `addons/` next to `addons/generated/`, without the
`Generated by deploy-talos.py` header: the app-of-apps syncs them and the
script never touches them.

## Remove an add-on

Remove its section and run `argocd`. Its generated files go, and the
app-of-apps deletes its Application, but not what it deployed (no cascade):
delete those resources yourself if they should go.
